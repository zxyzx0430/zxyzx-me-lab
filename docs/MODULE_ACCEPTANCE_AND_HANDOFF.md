# 全站模块设计、验收、归档与跨线程交接协议 v1.0

> **执行原则：每个模块都先独立设计、独立预览、由用户验收，然后归档锁定、生成交接说明，再开始下一个。** 用户对 M01 明确要求以后每个模块也这样做。此流程适用于 M01—M09 以及未来新增模块。

## 1. 模块从概念到交付的五个状态

| 状态 | 满足条件 | 可否进入正式整合 |
|---|---|---|
| ① Idea / 构思 | 说明面向谁、回答什么问题、与前后模块的关系、参考方向 | 不可 |
| ② Design draft / 设计草稿 | 完整视觉方案与动效分镜，内容候选和架构草案 | 不可 |
| ③ Working preview / 可运行预览 | 独立页面及真实交互；桌面/手机验收，初步自检 | 不可 |
| ④ **Visual approved / 视觉已认可** | 用户明确认可画面和交互；版本封存；有固定截图与交接 | 可以作为最终封装的视觉基线，**仍非生产就绪** |
| ⑤ Integration ready / 可集成 | 真正的模块消费入口与独立样式/素材、契约、回归测试、集成边界、用户验收 | 可以合并到站点组合层 |

**严禁把 visual approved 直接等同于上线、框架重构已完成、动效已完全复现或所有设备适配完成。** 视觉和工程是不同的双轴状态。

## 2. 每个模块必须保存的设计母稿

在 \`docs/module-designs/<MODULE>_<TOPIC>_*.md\` 保存以下真实信息（没有的标 \`TBD\` 而不是编造）：

1. **ID / 唯一职责 / 位置**：模块为何存在、给访客的信息是什么、明确不负责什么。
2. **思想与叙事**：核心隐喻、用户想表达的观点、与上一幕及下一幕怎样接。
3. **视觉系统**：布局与层级、摄影/项目素材、色板、字体和字重、反差、负空间、动效整体语法。
4. **内容与导航**：确切通过的文字、候选文案、所有必要点击入口与目标路径。
5. **交互分镜**：初始状态、入场/停留/离场、每种交互会发生什么、反向路径、减少动态效果方案。
6. **技术与边界**：唯一源文件和资产、组件公共接口、共享导航、路由、测试工具、外部依赖。
7. **用户选择记录**：明确哪些得到认可、哪些只是 Agent 建议、哪些被否定及原因；不要把助手建议写成用户确认。
8. **验证结果**：实际看过哪些桌面/手机分辨率、脚本与资源检查、布局差异、已知问题。
9. **版本与不可变基线**：模块预览链接、固定截图验收网址、源代码路径、SHA / Git 标签、日期、用户批准范围。
10. **后续事项**：可能的 V2、独立模块封装、正式集成、其他模块合作接口。

设计稿应解释「**为什么这样设计**」，而不只是描述结果，确保新线程可以按思想延续，而不是机械复刻像素或推翻。

## 3. 每次设计完成的冻结清单（可复制执行）

- [ ] 用户已看过真实网页或可检验视觉，明确认可具体模块版本。
- [ ] 设计母稿已写入 \`docs/module-designs/\`，文案、版式、动效和前后模块接口可复现。
- [ ] 独立预览能打开，资源加载正常，不指向未授权的私人素材。
- [ ] **固定截图验收入口**与该版本截图存在；移动端可打开；中文字体、文字和人像检查无异常。
- [ ] 截图分辨率遵从模块约定。**M01 固定为 1920×1080；用户明确不需要 1440×900。**
- [ ] 用实际设备/浏览器看桌面及手机，记录真实测到的宽度和问题；自动化测试不是用户审美批准。
- [ ] Git 变更只涉及本模块、对应设计文档/公共配置，\`git diff --name-only\` 审查通过。
- [ ] \`node scripts/validate-modules.mjs\`、模块自己的测试、浏览器冒烟测试完成；失败要注明。
- [ ] 在认可后的提交上打**不可覆盖的视觉基准 Git tag**，并注明批准范围。
- [ ] 给出给下一线程的路径、链接、冻结点、当前范围、未来工作与明确不许动的模块。
- [ ] 新模块开始前，先确认原模块不会被意外修改。

不允许自动将 draft 升级为 approved；没有用户明确认可不得打“已认可”标签。

## 4. 实施改版与风险处理

- **新版本新分支**，例如 \`feat/m02-work-portal-v1\`；保留已认可 Git tag / 历史素材。
- 静态视觉已经确定时，技术架构重构只做无差别迁移；严禁趁机“顺手重新设计”。
- 网站组合层只管全局导航、路由、页面衔接、响应式容器；不能跨模块修改隔离组件内部。
- 模块内部可改变自己的状态和动画；**跨模块转场的最终控制权由组合层承担**，不得让一个模块接管其他模块滚动/样式。
- 若素材文件更换，记录真实来源和是否 AI 生成、是否用户提供；保护真人肖像和私人信息。
- 若新改动导致已认可的效果退化，保留旧版本并可以迅速回滚，不能删除老版后要求用户接受退步。
- 用户反映像素细节、中文字体、交互体验问题时，优先**实际截图 + 浏览器操作复测**，不要只口头说明 CSS 应该正确。

## 5. 交接结构与来源优先级

优先顺序：用户最新明确选择 > 已批准设计母稿和 tag > 已验收的实际预览 > 最新工程草稿 > Agent 建议。

新线程第一次工作要执行：
1. 读 \`AGENTS.md\` / \`docs/MODULE_STANDARD.md\` / 本协议。
2. 读 \`docs/module-designs/<ID>...md\` / 对应模块 README / 注册表。
3. 看当前批准预览和截图站；读批准 tag；不要误用旧草稿。
4. 报告自己理解的模块职责、已冻结点、未冻结点、待做任务。
5. 仅对用户明确要求的范围动手。

**交付报告最少包含：** 模块 ID、状态、批准的是什么、原稿/最新代码路径、预览 URL、截图站、提交 SHA、标签、测试结果、遗留问题、下一步。

## 6. 目前模块路线（只是设计分工，不等于全部做完）

- **M01**：人物电影式首页 / identity opening → 视觉批准（V3）。
- **M02**：精选作品入口 / Selected Works → 设计阶段。
- **M03**：Personal AI System 项目世界（包含受保护 Knowledge Network V5）。
- **M04**：Open Margin / 清衡项目世界。
- **M05**：Hardware RAG Agent 项目世界。
- **M06**：About Me，个人经历、摄影与理解世界的方式。
- **M07**：Ideas，经济、商业、教育、AI 等思想札记。
- **M08**：Now，最近正在做的事与更新轨迹。
- **M09**：Contact / 结尾。

网站总体仍为「电影式首页 + 独立项目世界」，M03–M09 的设计均尚未批准；不要把此路线直接写成已开发页面。
