## 0. 为什么需要 M02

- M01 回答「这个人是谁、如何看待自我与世界」，M02 要回答 **「这样的思考最终创造出什么？」**
- M02 既要自然回应 M01 的「向外探寻世界」，又要让三个完全不同的项目各有吸引力；不是线性简历，也不是企业官网的三张卡片。
- 模块职责：精选作品的**视觉导航大门**，以少量文字和有识别度的内容预告，引导访客**点进独立项目世界**。
- 不承担：三个项目的完整技术文档、长篇市场分析、全部功能展示、知识网络 V5 的直接改造、个人简历、博客全文。

## 2. 与 M01 的叙事关系

**M01：向内寻找中心 / 向外探寻世界** → **M02：思想，进入现实**。

M01 的暖白、巨大黑字、黑白人物摄影已经很强。M02 可以在视觉上**突然改变材质和节奏**：从人物肖像切向项目场景。对比是真正有叙事意义的（从“人”到“作品”），不是随便换背景炫技。

当前 M01 原型已有暗色的“思想，进入现实”过渡占位；它**不是已认可的 M02 页面**。M02 要为这段转场设计正式的画面/文案，再由未来整站组合层拼接。单独开发 M02 时绝不以改写 M01 为前提。

## 3. 值得深入比较的三个设计方向（仅供探索）

### A · 电影片名 / Cinematic Titles（推荐作为第一轮主研究）

每个项目不是相同矩形卡，而像一部电影的**不同片章**：一个巨型作品编号，一段有表现力的短标题，一张大幅真实视觉，微小的作品类型标签。项目切换像片名之间的剪辑。

- 视觉：大图摄影/真实项目 UI + 片名式超大文字 + 高比例留白，具有明确的前后幕。
- 运动：随着翻幕，上一项目的主体被裁切离场，下一项目从不同方向被揭示；每部作品必须有独立气质，避免统一淡入效果。
- 优势：呼应 M01 的电影性；访客不需先懂技术，也能对作品产生好奇。
- 风险：项目素材质量必须够好；不能用千篇一律的 AI 科技概念图填充。

### B · 先锋编辑封面 / Experimental Editorial

项目入口像三本不同主题的实验杂志，采用大胆的杂志目录字号、错位构图、裁切 UI 片段与简短项目摘要。

- 优势：信息密度与视觉美感兼顾，容易继续表达项目背后的思想。
- 风险：如果使用同样大小的标题且贴太多装饰，容易重现旧版 M01 巨字拥挤的问题。

### C · 交互展馆 / Curated Museum

先出现一个清晰的“作品索引”，用户指向/点击某个项目后，环境与项目素材发生大范围变化：变色、局部视频、深度或水平/纵向切换。

- 优势：适合多作品日后扩充，浏览体验有主动探索感。
- 风险：复杂导航在手机端或触控板上很可能变得费劲；**不能再次要求长距离滑动才能切换项目**。

## 4. 第一次正式讨论建议检查的议题

1. **作品出现顺序**：哪一个最能表达你现在的身份？可以先提出 Personal AI System → Open Margin → Hardware RAG Agent 作为**未确认候选**，不是固定排名。
2. **第一眼是作品画面还是项目名称？** 应优先保留真实内容的视觉吸引力，标题只辅助识别。
3. **展示深度**：首页 M02 每个项目只给一个视觉片段、一句定位和一个深入入口，还是需要更丰富的信息？避免把 M03/M04/M05 的工作提前做完。
4. **过渡节奏**：从 M01 的静谧肖像到 M02 的世界，使用明暗骤变、形状揭幕、全屏翻片还是镜头移动？要兼容一滑一页。
5. **主题变化自由度**：三个项目可拥有自己配色，品牌导航和基本可访问性仍稳定。
6. **素材真实性**：哪些项目真实运行截图或视频可公开展示，哪些仍需制作无真实隐私的概念图？
7. **手机端路径**：无 Hover 也必须能识别、进入作品；默认不强制等动画结束才可点击。

## 5. 我倾向的首版信息结构（仍待用户选择）

```text
M01 FINAL FRAME
  → Transition: 思想，进入现实（过渡命题，尚未确认文案）
  → M02 / SELECTED WORLDS
      01 Personal AI System ── 视觉预告 + 1句真实定位 + ENTER WORLD
      02 Open Margin       ── 视觉预告 + 1句真实定位 + ENTER WORLD
      03 Hardware RAG Agent── 视觉预告 + 1句真实定位 + ENTER WORLD
  → M03/M04/M05 独立项目页（未来）
  → 再回到个人叙事 / M06 ...
```

不是普通三卡组件，也不需要在一个屏幕内展示全部信息。可以探索一屏一部作品、局部重叠的片段与动态索引，但**一滑一页**应作为跨模块核心体验约束；不能延续过去“滚 170svh 才换一幕”的问题。

## 6. 技术边界与未来接口

- 未来独立模块建议 ID：`selected-works`（未创建/未注册），页面用于容纳多项目入口；数据集中管理标题、项目 slug、媒体来源和路线，而不在动画里硬编码大量字符串。
- 可独立运行，可被组合层接到 M01 后，不读取或修改 M01 Shadow DOM，不影响已批准 V5。
- 真实链接如 `/work/personal-ai/` 等是**规划路径**，正式路由未上线之前，预览中明确标识 TBD，不使用伪装的可点击死链接。
- 视口切换与动画要避免强制滚轮拦截冲突：整站组合层决定全局翻页，M02 只提供单模块内容与进出状态接口。
- 正式开发要使用 `templates/module/` 规范和模块验收流程，单独保存视频、图、字体或截帧素材来源。

## 7. 本阶段如何定义“完成”

当前只建立 M02 设计启动思路，没有批准视觉，没有原型。完成 M02 需：
- 拿到用户对主视觉方向、内容结构与素材的认同；
- 制作真正可看的独立 M02 首版，视觉与 M01 具有对照但非互相覆盖；
- 按 `docs/MODULE_ACCEPTANCE_AND_HANDOFF.md` 验收、截图站、锁定 tag、交接；
- 不提前合并至正式 `zxyzx.me`。
